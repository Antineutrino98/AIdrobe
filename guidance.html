AIdrobe 使用手册

说明当前版本每个按钮做什么、每个选项什么含义。第一次用建议按顺序读第 1–4 节。

1. 启动与关闭

双击 AIdrobe.exe。程序会在后台起一个本地服务，然后自动打开浏览器页面。

  • 地址通常是 http://127.0.0.1:8000；8000 被占用时会自动顺延。
  • 关掉浏览器页面，后端会在几秒内自己退出，任务管理器里不会留进程。
  • 想立刻关：系统托盘图标右键 →「退出（会先保存数据）」。
  • 同一时间只能开一个实例，第二个会提示数据库已被占用。
第一次启动会初始化数据库，可能要十几秒。之后启动通常在 5–10 秒内完成。

2. 模型设置（第一次必须做）

点顶部「模型设置」，粘贴 API Key，然后三个角色各选一个模型。

2.1 三个角色分别管什么

角色负责的事建议
入库识别 / 品类判断看照片判断品类、颜色、材质、正式度、保暖度选便宜且能看图的
文本规划 / 查重 / 偏好决定从衣橱哪几类里挑候选；判断买的新衣和现有的是否重复选便宜的文本模型即可
搭配决策（看图）真正挑衣服、给成套结果和理由。必须能看图选看图能力强的

2.3 测试连接

点「测试连接」，会逐行显示结果：

  • 后端连接：只证明程序本身活着。
  • 三个角色：各自真实调用一次模型，显示耗时。
  • 报错会被翻译成人话，例如「密钥没有该模型的权限」「额度或频率受限」「网络连接失败」。

3. 入库

「入库」里可以选图片（可多选），也可以贴商品链接。

  1. 上传后模型会识别品类、颜色、材质、正式度、季节、风格、场合等属性。
  2. 如果它拿不准品类，会给出两个候选让你确认，选一个即可。
  3. 入库完成后可以在「我的衣橱」里看到，也能补备注。
识别质量取决于照片：单件平铺或挂拍、光线均匀、背景干净，识别最准。 一张图里有多件衣服时，只会识别最显眼的那一件。

4. 穿什么（搭配）

选场景（上班 / 约会 / 周末 / 旅行 / 正式场合）、填城市，点「给我搭配」。

4.1 天气

填城市名会自动查当地当天天气，结果显示在推荐上方一行：城市、温度区间、天气、温差。 温差大的时候会提示「留了可以随时增减的外层」。

4.2 搭配结果怎么看

  • 每套有风格名（如「极简通勤」）、涉及的衣服缩略图和一段中文理由。
  • 一套不一定是三件。可能是 T 恤 + 衬衫 + 外套三层，也可能是连衣裙配鞋。
  • 理由里会说明配色关系、正式度是否一致、厚薄是否合适。
  • 评分 1–10 是模型对这套搭配的自我判断，不是你的偏好。

4.3 反馈

每套搭配下面有「喜欢 / 不喜欢 / 今天穿了」。

  • 点「今天穿了」会把这套里每件衣服都记上今天的穿着日期，之后按「穿着间隔」策略决定什么时候能再出现。
  • 「喜欢 / 不喜欢」会被累积成你的风格偏好，下次搭配时参考。

4.4 如果不完整

衣橱里缺某类衣服时（比如没有鞋），页面会明确写「衣橱里没有可用的鞋」。 这时仍然会给搭配，只是不完整；补上这类单品后重新生成即可。

5. 买不买

贴一件想买的衣服（图片或链接），程序会回答「买 / 再想想 / 别买」，并说明：

  • 能和现有衣橱凑出几套；
  • 覆盖哪些场合；
  • 和已有单品重复的风险有多高。

判定有硬规则：凑不出任何一套、或者重复风险很高时，不会给出「买」。

6. 缺口

统计衣橱后告诉你缺什么，例如「通勤场合缺少正装鞋」。 结论只基于统计事实，不会凭空建议你买。

7. 我的衣橱

  • 按品类分组，每组可以单独折叠；整块也可以收起。
  • 点任意一件看详情：品类、细分、颜色、图案、材质、正式度、季节、风格、场合、保暖度、穿着记录和备注。
  • 详情里有「扔掉了 · 删除」，会二次确认，删除后不可恢复。
删除衣物会同时删掉这件衣服相关的推荐记录与反馈。图片文件保留在 data 目录里，不会污染新数据。

8. 推荐策略

点顶部「推荐策略」。策略按用户分别保存。

设置含义
刚穿过的衣服随时可再穿 / 昨天穿过今天不推荐 / 穿过后隔 2、3、7 天再出现
上班穿成什么样很商务 / 商务休闲 / 无着装要求。只影响「上班」场景
候选优先级均衡 / 优先没怎么穿过的 / 优先新入库的
每次至少生成几套3–5 套
该洗了、洗衣中的衣服永远不会进推荐，这是程序保证的，不需要设置。 「穿过一次」不算脏，能不能接着穿由「刚穿过的衣服」那一项决定。

9. 请求日志

顶部「请求日志」记录每次请求的状态和耗时，全中文显示（如「提交推荐搭配 · 成功 · 127 秒」）。 搭配失败时先看这里，能直接看出是超时、无权限还是服务端出错。

10. 常见问题

搭配要等一两分钟，正常吗？
正常。搭配要把多张衣服照片一起发给模型，单次调用通常 1–2 分钟。 如果超过 5 分钟没反应，看「请求日志」和 logs/aidrobe.log。
提示「密钥没有该模型的权限」
这把 Key 没开通对应模型。换一个有权限的 Key，或在「模型设置」里换模型。
页面显示「无法读取用户列表」
后端没起来或正在启动。等几秒刷新；仍不行就看 logs/aidrobe.log。
能不能两个人共用一个程序、各自一个衣橱
可以。顶部切换用户即可，衣橱和策略都按用户隔离。
数据存在哪，怎么备份
全部在 data/ 目录。备份就是复制整个目录，恢复就是覆盖回去。
换了电脑怎么办
把整个文件夹（含 data/、dist/、.env）复制过去即可。
