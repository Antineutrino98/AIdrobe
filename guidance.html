AIdrobe 使用手册

说明当前版本每个按钮做什么、每个选项什么含义。第一次用建议按顺序读第 1–4 节。

从 v1.0 升级到 v2.0 后，请在设置页重新填写一次 API Key，之后即可永久保存在本地。 桌面版采用全新的底层渲染引擎，浏览器时代保存的 Key 无法带过来；这一步只需做一次。

1. 启动与关闭

双击 AIdrobe.exe。程序在后台启动本地服务，然后弹出一个独立的桌面窗口： 没有地址栏、没有书签栏，也不会弹出命令行黑框。

  • 窗口内部访问 http://127.0.0.1:8000；端口被占用时会自动顺延，平时不需要关心。
  • 点右上角 X 不会立刻消失。窗口先最小化到系统托盘，并弹出气泡 「正在保存衣橱数据并安全退出...」。等数据保存完程序才完全退出，请等候几秒，这不是卡死。
  • 系统托盘图标右键可以「打开界面」或「彻底退出」。
  • 同一时间只能开一个实例。再次双击不会启动第二个服务，而是把已经打开的窗口重新显示出来。
  • 启动初期托盘会提示「AIdrobe 正在唤醒衣橱，请稍候...」。
第一次启动要初始化数据库，可能要十几秒；之后通常在 5–10 秒内完成。

2. 设置（右上角齿轮）

顶栏只放当前用户切换和一个齿轮。点齿轮打开设置抽屉，高级配置都收在这里：

分区内容
运行状态密钥是否就绪、今日已生成几套搭配、消耗约多少 tokens
模型与 API进入「模型设置 / 测试连接」
衣橱范围只看我的 / 全部衣橱
用户与偏好管理用户、推荐策略
诊断请求日志

2.1 三个角色分别管什么

角色负责的事建议

目前共 13 个模型，分属 5 家服务商。每家只填一次自己的密钥，用到哪家填哪家， 没选的模型不要求填 Key。

后三家需要服务商提供 OpenAI 兼容接口，程序会把模型名和接口地址一起保存。 能不能读到图由「测试连接」实测判定，程序不会预设某个模型不能看图。

搭配决策必须用「能读到图」的模型。用「测试连接」验证：它会真的传一张纯红色的图， 如果那一行标了「读图异常」，说明这个模型或这套接口确实没看到图， 换一个模型，或者检查接口地址是否填对。

2.3 保存与立即生效

Key 保存在本机的 .env 文件里，界面只显示前后 4 位（如 sk-1****abcd）。 保存后立即生效，不用重启程序；带星号的显示值不会被写回去覆盖真 Key。 清空输入框再保存，等于删除这个角色的 Key。

2.4 测试连接

点「测试连接」，会逐行显示结果：

  • 后端连接：只证明程序本身活着。
  • 三个角色：各自真实调用一次模型，显示耗时。
  • 报错会被翻译成人话，例如「密钥没有该模型的权限」「额度或频率受限」「网络连接失败」。

3. 首页

首页是仪表盘，不是功能区：左边是「今天穿什么」的入口， 下面有模型状态卡（密钥是否就绪）、今日使用统计（生成几套、消耗多少 tokens）， 以及最近收进衣橱的几件衣服。点按钮会跳到对应页面，具体功能仍在各自页面里完成。

4. 我的衣橱与入库

「我的衣橱」右下角有「添加衣物」按钮，点开后可以选图片（可多选），也可以贴商品链接。

  1. 上传后模型会识别品类、颜色、材质、正式度、季节、风格、场合等属性。
  2. 如果它拿不准品类，会给出两个候选让你确认，选一个即可。
  3. 入库完成后可以在「我的衣橱」里看到，也能补备注。

衣橱按品类分组，每组可以单独折叠；点任意一件看详情：品类、细分、颜色、图案、材质、 正式度、季节、风格、场合、保暖度、穿着记录和备注。详情里可以标记待洗或删除，删除会二次确认。

识别质量取决于照片：单件平铺或挂拍、光线均匀、背景干净，识别最准。 一张图里有多件衣服时，只会识别最显眼的那一件。
删除衣物会同时删掉这件衣服相关的推荐记录与反馈。图片文件保留在 data 目录里。

5. 穿搭推荐

选场景（上班 / 约会 / 周末 / 旅行 / 正式场合）、填城市，点「给我搭配」。

5.1 天气

填城市名会自动查当地当天天气，结果显示在推荐上方一行：城市、温度区间、天气、温差。 温差大的时候会提示「留了可以随时增减的外层」。

5.2 搭配结果怎么看

  • 每套有风格名（如「极简通勤」）、涉及的衣服缩略图和一段中文理由。
  • 一套不一定是三件。可能是 T 恤 + 衬衫 + 外套三层，也可能是连衣裙配鞋。
  • 理由里会说明配色关系、正式度是否一致、厚薄是否合适。
  • 评分 1–10 是模型对这套搭配的自我判断，不是你的偏好。

5.3 反馈

每套搭配下面有「喜欢 / 不喜欢 / 今天穿了」。「今天穿了」会给这套里每件衣服记上穿着日期； 「喜欢 / 不喜欢」会累积成风格偏好，下次搭配时参考。

5.4 如果不完整

候选池说明会告诉你哪些品类没有入选；补上这类单品后重新生成即可。

6. 购前决策与衣橱缺口

贴一件想买的衣服（图片或链接），程序会回答「买 / 再想想 / 别买」，并说明 能和现有衣橱凑出几套、覆盖哪些场合、重复风险有多高。判定有硬规则： 凑不出任何一套、或者重复风险很高时，不会给出「买」。

同一页下方是「衣橱缺口」：统计后告诉你缺什么，例如「通勤场合缺少正装鞋」。 结论只基于统计事实，不会凭空建议你买。

7. 推荐策略

设置抽屉 →「推荐策略」。策略按用户分别保存。

设置含义
刚穿过的衣服随时可再穿 / 昨天穿过今天不推荐 / 穿过后隔 2、3、7 天再出现
上班穿成什么样很商务 / 商务休闲 / 无着装要求。只影响「上班」场景
候选优先级均衡 / 优先没怎么穿过的 / 优先新入库的
每次至少生成几套3–5 套
该洗了、洗衣中的衣服永远不会进推荐，这是程序保证的，不需要设置。 「穿过一次」不算脏，能不能接着穿由「刚穿过的衣服」那一项决定。

8. 请求日志与错误提示

设置抽屉 →「诊断」里的请求日志记录每次请求的状态和耗时，全中文显示 （如「提交推荐搭配 · 成功 · 127 秒」）。搭配失败时先看这里。

模型出错时不会显示红色堆栈，而是给中文提示： 「你的 AI API Key 已失效或余额不足，请检查设置」，或「造型师今天灵感枯竭，请再试一次」。 前者去设置页更新 Key，后者稍等再试一次即可。

9. 常见问题

升级到 v2.0 后，为什么提示要重新填 Key？
桌面版换了底层渲染引擎，浏览器时代存在 localStorage 的 Key 带不过来。 在「设置 → 模型设置」重新填一次，之后就固定保存在本机 .env 里， 以后升级不用再填。
点了 X，窗口不见了但托盘图标还在，是卡死了吗？
不是。程序正在保存衣橱数据并安全退出，托盘气泡会写明进度。等几秒进程会自己结束， 这期间不要强制结束任务，以免数据没写完。
提示「造型师今天灵感枯竭，请再试一次」
模型这次返回的内容没法解析，或者请求超时。再点一次通常就好； 连续出现请看设置抽屉里的「请求日志」和 logs/aidrobe.log。
搭配要等一两分钟，正常吗？
正常。搭配要把多张衣服照片一起发给模型，单次调用通常 1–2 分钟。 如果超过 5 分钟没反应，看「请求日志」和 logs/aidrobe.log。
提示「密钥没有该模型的权限」
这把 Key 没开通对应模型。换一个有权限的 Key，或在「模型设置」里换模型。
页面显示「无法读取用户列表」
后端没起来或正在启动。等几秒刷新；仍不行就看 logs/aidrobe.log。
能不能两个人共用一个程序、各自一个衣橱
可以。顶栏切换用户即可，衣橱和策略都按用户隔离。
数据存在哪，怎么备份
全部在 data/ 目录。备份就是复制整个目录，恢复就是覆盖回去。
换了电脑怎么办
把整个文件夹（含 data/、frontend/dist/、.env、 alembic/）复制过去即可；新电脑需要 Edge WebView2 Runtime。
